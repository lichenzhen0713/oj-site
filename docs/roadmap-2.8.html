已发布的记账版本#

版本内容摘要状态
v2.7.9后台「功能开关」→「功能设置」（齿轮图标）；全站积分结算（默认实时 / 定时 / 手动，间隔支持小时·天）；通信题新题型（两个程序、管道直连与评测端中转）；修复通信题搭配特殊评测误报 System Error；若干界面细节已发布（服务待重启生效）

每批的验收口径（统一要求）#

  1. 真实运行验证：功能必须用真实接口 / 真实评测 / 无头浏览器量化（getBoundingClientRect、计算样式、对比度）取证，不接受"看起来没问题"。
  2. 不破坏判题语义：普通题、IO 交互题、函数式交互题、通信题四类必须各跑一次 AC 回归。
  3. 不破坏样式基线：public/css/style.css 的 2.6.3 基干逐字节不变，新样式只追加到文件末尾。
  4. 数据安全：测试若改库 / 改 testdata，必须还原并给出前后对照；不动 theme_* 与站点内容数据。
  5. 收尾：node --check、U+FFFD=0、缓存号递增、/ 与 /api/health 200、80 端口唯一 node 实例、临时文件清理。
  6. 并发纪律：同一时间只允许一个执行者改同一批文件；改动前重读磁盘、只用定点替换、禁止 PowerShell 文本管道改源码（历史上曾因此损坏 src/judge.js 1008 处中文）。

风险与待决事项#

  • 积分结算性能：实时模式每 60 秒全量重算 1371 人并写快照（实测单轮 3.5 ~ 21 秒，单批最长约 2 秒）。因实时模式下页面本就取实时值，建议实时模式不再周期性写快照（或把周期拉长）。
  • 通信题范围：目前仅支持 C/C++；direct 模式含 5 秒冷启动宽限、内存只采样程序二。
  • 验证用测试提交：#45066–#45107（通信题与回归验证）待站长决定是否清理。
  • 投稿 500：站长尚未复现；服务已带日志运行（logs/server.err.log），复现后可立即定位。
